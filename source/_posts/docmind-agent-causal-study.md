## 为什么做消融

DocMind 是我的 RAG Agent 系统。它用 PER 架构——Plan(规划)、Execute(执行)、Reflect(反思)三个阶段,内置 25 个以上的工具,能做到问答、对比、分析、研究。

系统能用,但我不知道它为什么好用。

这是做系统的人经常有的状态:整体是好的,拆开说不清楚。多 Agent 协作、LangGraph 编排、DAG 并行执行——每一个名词背后都是钱和时间,但我没有一个实验能回答:去掉这些,系统会变差多少?

于是有了这个项目:七组对照实验,一组一组做,记录、分析、存档。研究做完之后,实验轨迹冻结在一个 commit 里,不再修改。

## 假设一:DAG 执行器应该比串行好

系统里有两个执行器:DAG,可以把相互独立的步骤并行跑;Serial,严格按顺序跑。

直觉上,DAG 一定更好。并行怎么可能输给排队。

实验结果:DAG 覆盖率 66%,Serial 69%。差三个百分点。

更关键的是平均步骤数:DAG 1.2,Serial 1.0。一个平均只生成 1.2 步计划的执行器,它的并行能力从头到尾没有被激活过。两个执行器其实在跑同一种工作负载。

这是这个实验系列的第一个发现,也是第一个被否掉的假设:**并行架构本身不产生价值,产生价值的是计划里可以并行的步骤。**

## 假设二:提示词能诱导 Planner 拆得更细

既然问题是"Planner 只生成 1.2 步",那就让它多拆几步。这是最直接的想法。

我们在系统提示里写了"尽可能细粒度拆分",然后用三档提示词分别测:coarse、normal、fine。

结果:coarse 生成 1.0 步,normal 1.1 步,fine 1.2 步。

三档提示词,平均步数一共涨了 0.2。

现代大模型的优化目标是尽快完成当前回合,一步完成任务对它来说成本最低、最省 token。你可以在提示词里写一百遍"请拆分",它还是会把三件事写进一段话里,然后一次做完。

第二个假设被否掉。而且这个否定比第一个更值得记录,因为它指向一个本质问题:**Planner 退化了。它名义上是个任务分解器,实际行为是个查询改写器。**

## 假设三:规则模板能提升覆盖率

前两个实验指向同一个答案:不要指望 LLM 拆任务。那如果拆任务这件事本身不用 LLM 呢?

我写了一套规则化模板,按任务类型分发:

- **comparison**(对比):固定生成"提取对象 → 分别检索 → 逐项对比 → 汇总结论"四步
- **analysis**(分析):"定位对象 → 收集证据 → 结构拆解 → 综合评估"
- **research**(研究):"拆解子问题 → 逐个子问题检索 → 交叉验证 → 汇总"

这不是高深的算法,就是一组 if-else 加模板字符串。用它对基线做对照:

| 指标 | 基线 | 结构化规划 | 变化 |
|------|------|-----------|------|
| L1 覆盖率 | ~69% | **93.1%** | +24 个百分点 |
| L1 失败数 | 5–6 | **0** | 全部消除 |
| 平均步骤数 | 1.2 | 3.4 | +2.2 |
| 平均耗时 | ~30s | 59s | +29s |

第三个假设成立:规则模板显著提升覆盖率。代价是耗时翻倍,但这个代价是可接受的——回答的质量从"经常答不对"变成"没答错过"。

## 假设四:DAG 在计划变长后会赢

到这里还欠 DAG 一个公道:之前的实验里它输,是因为计划太短。那如果计划变长,比如 4–7 步,DAG 的并行价值应该会显示出来。

结果:DAG 并行执行 4–7 步计划时,步骤数增加 180%,耗时只增加 95%。

亚线性。并行的价值在这个尺度上出现了,只是它挽救不了 1.2 步的计划。

第四个假设部分成立,但这部分成立不再重要。因为正确的顺序是:**先让计划变长,再谈并行。** 步骤从 1.2 到 3.4 带来的 +24 个百分点,远大于执行架构选择带来的 ±3 个百分点。

## 第五个实验:复测

把 DAG 和 Serial 在结构化规划条件下再跑一遍,确认结论稳定。结果和第一次一致:两者差距在误差范围内。

研究结论写进了 README 的第一段,原文是一句很硬的话:

> 规划质量远比执行架构重要。

翻译成大白话:别让 LLM 决定拆不拆。你来决定。

## 附带的发现

实验还暴露了一个被忽略的事实:失败数从 5–6 降到 0,不是因为模型变强了,而是因为模板把"分析苹果"这种问题也变成了多步任务,每一步都有明确的产品;覆盖率从 69% 到 93.1% 的跃迁,主要来自"把要做什么说清楚"。

另一个数据值得记录:评测体系是 30 题三层。L1 能力层 20 题,覆盖率 93.1%;L2 系统层 10 题,只有 50%,5 个 FAIL 全是"今天天气怎么样""分析苹果"这类歧义和边界查询——模型会认真地给一个错误回答,而不是承认不知道。这类问题不在 L1 的判定范围内,它们被如实记在结果里。

## 方法论的副产品

这个项目真正留下的,不是那套模板,而是一份否定的轨迹。

研究路线图里,五个假设四个打了叉,每个叉都连着一次实验、一组数据、一段分析。001 到 005,形成一条完整的链:DAG ≈ Serial → Planner 不可诱导 → 模板有效 → DAG 仍不关键 → 复测确认。

做研究的人知道,这条链比任何一次成功都值钱。因为成功的结论可以被复制,失败的路径不能——它是用实验成本换来的。

项目仓库冻结在 2026-06-28 的 commit 上,声明不再修改。生产实现迁移到了 DocMind-RAG 仓库继续演进,那里有 422 个测试。

五个假设,否了四个。剩下那个,用了二十九秒多的时间,换来了二十四个百分点的覆盖率。
