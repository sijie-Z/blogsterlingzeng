读到一半点开脚注，回来找不到原来的句子。想确认一个陌生名词，要开新标签页。文章底部写着相关阅读，但那只是标签相似，不是有人真的引用过。

三个场景，都是长文的常见断点。博客是静态的，站内跳转用 Swup，只替换 `#swup`。我想要的效果不是多几个弹窗，而是这些上下文能在当前位置出现，并且不增加首屏请求。

## 先把约束写清楚

- 构建产物部署在 GitHub Pages，没有常驻服务端。
- Swup 换页只替换 `#swup`，`<head>` 不会重新加载。
- 首屏不为这些功能让路，能构建期完成的不放到运行时。
- 所有交互要能用键盘完成，`Esc` 要能退出。

上一轮做[静态资源清理](/2026/10/23/static-assets-cleanup/)时，把首屏从 33MB 压到 22MB；这一轮不想为了几个阅读功能把请求加回去。

后面的每个功能，都是在这四条约束里找解。

## 边注：构建期生成，宽屏进页边

边注的语法是一个 Hexo 标签：

```markdown
{% margin %}212px 是注释列宽，235px 是 1680px 下正文左侧的可用页边。{% endmargin %}
```

构建时把标签内容按 Markdown 渲染，输出一个引用标记和一条注释。注释不是弹窗，是一段真实的 DOM，只是默认不占正文宽度。

宽屏阈值是量出来的：1680px 时正文宽 957px，左侧页边 235px；1440px 时正文左侧只剩 143px。注释列需要 212px，所以只在 ≥1680px 时浮进页边，窄屏改成点击 ※ 打开的底部卡片。{% margin %}212px 是注释列宽，235px 是 1680px 下正文左侧的可用页边，两者相减剩下的 23px 是间距。{% endmargin %}

底部卡片有一个容易忽略的问题：正文祖先带着 Swup 入场动画的 `transform`，`position: fixed` 会相对这个祖先定位，而不是视口。卡片的解法是把它挂到 `body` 上，和边注、预览卡用同一套思路。打开时焦点进入关闭按钮，`Esc` 收起后焦点回到引用。

## 链接预览和脚注预览：只在需要时出现

站内链接的预览数据在构建期生成：32 条记录，约 10KB，gzip 后 4KB。第一次悬停才会请求，之后复用。

桌面端悬停 300ms 才显示，卡片固定在视口内，`pointer-events: none`，不会挡住鼠标。它是 `role="tooltip"`，不进入 Tab 顺序。触屏设备不接管点击，直接跳转。

脚注预览复用构建期的 `#fn-*`，悬停或键盘聚焦时把正文克隆到小卡片里，点击引用仍然跳到文末。两者都不发新请求。

## 引用与反向链接：把“被别人引用”变成构建期索引

引用元数据放在静态 HTML 的 head 里：`citation_title`、`citation_author`、`citation_publication_date` 等，供 Google Scholar 一类服务抓取。

侧栏的分享按钮改成了菜单，可以复制 Markdown、BibTeX、APA、GB/T 7714、RIS 和链接。菜单读的是正文里的 JSON，不是 head。原因前面写过：Swup 只替换 `#swup`，head 不会跟着换页更新；如果读 head，第二篇文章会复制到第一篇的引用。

反向链接是另一个方向：不是“这篇文章引用了谁”，而是“谁引用了这篇文章”。构建期扫描所有文章的正文内链，在目标文章底部列出最多 5 条来源和引用处的上下文。当前 23 篇文章里有 18 篇至少被引用一次，没有来源的文章不渲染空区块。

这里踩过一个构建期问题：解码 HTML 实体时，`&#x110000;` 这种超出 Unicode 范围的码点会让 `String.fromCodePoint` 抛错，整个文章页渲染失败。现在先校验码点范围，非法实体原样保留；反向链接索引也在每次 `generate` 前重置，`hexo server` 下不会一直用旧数据。

## 阅读设置：在首屏前应用

文章多的站需要目录，也需要[系列阅读](/2026/10/23/hexo-series-reading-path/)；系列解决的是“按什么顺序读”，阅读设置解决的是单篇读起来舒不舒服。

字号有三档，专注模式会收起目录和相关阅读、把正文限制在 860px 并居中。设置存在 localStorage，但真正难的是首屏：如果等脚本执行完再改字号，页面会先按 16px 排一遍，再跳一次。

解法是 head 里一段内联脚本，在首屏绘制前把 `data-read-size` 和 `cj-focus` 写到 `<html>` 上；CSS 直接按属性生效，没有第二次布局。窄屏没有侧栏，左下角的 Aa 按钮打开底部设置卡，和引用按钮上下排开。

## 一个被测量否决的方案

这轮还认真评估了按页拆 CSS/JS。Chrome coverage 的数字很诱人：custom.css 单页只用到 14%–30%，custom.js 29%–40%。

但 Swup 只替换 `#swup`。按页注入到 `<head>` 的样式表，首次打开有效，站内跳转后不会加载。正确做法是把 `<link>` 放进被替换的正文，或者加运行时 loader；前者会闪烁，后者要处理加载顺序和重复执行。收益大约 8–10KB gzip/页，抵不过这两项成本，所以暂时不做。

同一轮还统一了导航胶囊和文章卡片的材质。滚动收缩后的胶囊原来有独立的 `backdrop-filter` 和另一种底色，和下面的卡片像两种玻璃；现在两者使用同一个背景变量和同一条描边，模糊都关掉。

## 结果

| 指标 | 结果 |
|---|---|
| 浏览器检查 | 442 项（其中阅读功能 84 项） |
| axe-core | 桌面/移动端 0 违规 |
| 首屏新增请求 | 0；链接预览在第一次悬停时取 1 个 JSON 和 1 张封面 |
| 部署产物 | 约 21MB |
| 反向链接 | 23 篇中 18 篇有至少一条来源 |

这些功能没有一个是新页面。它们只是把已有的信息放到读者需要的位置：边注放在页边，引用放在菜单里，反向链接放在文末，阅读设置放在首屏之前。

下一次要处理的是 Cloudflare 的缓存规则和图片查看器的手势，不是再加一个弹层。
